# Workshop (3D Build Space) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native, chosen by the user's "spec out and build" directive). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Workshop tab to jarvis-deck: a three.js 3D viewport where JARVIS builds, explodes, labels, inspects and edits objects from natural-language prompts via structured scene JSON.

**Architecture:** Backend emits/patches scene JSON through Gemini direct calls (`gemini-2.5-flash` + `responseSchema`, the `/vision/analyze` pattern), persists to `~/.hermes/agentos/cache/workshop-scene.json`, and returns it to a deterministic three.js renderer (`Workshop3D` component). All visual behavior (shapes, explode, labels, picking) is deterministic frontend code driven by the schema in the spec.

**Tech Stack:** FastAPI router (existing), urllib Gemini call, three 0.187 (`three/examples/jsm/controls/OrbitControls.js`), react jsx-runtime conventions of `desktop/plugin.js`.

**Spec:** `docs/superpowers/plans/2026-11-12-workshop-spec.md` (same directory).

## Global Constraints

- Backend deps stay stdlib + fastapi + yaml (no new pip deps).
- Gemini calls require `GEMINI_API_KEY` from `_read_env()` — 409 with actionable detail when missing.
- Scene limits: ≤ 48 parts, label ≤ 60 chars, desc ≤ 300 chars, |pos| ≤ 20, colors match `^#[0-9a-fA-F]{6}$`, shapes limited to the spec enum; malformed parts dropped, never a 500.
- Speech strings capped at 600 chars (sentence boundary) — reuse the `_SPEECH_CAP` pattern.
- Frontend: jsx-children-in-props (never 3rd arg of `jsx()`), hooks from the top import list, no `React` namespace, every new component mounts cleanly inside `WidgetBoundary`.
- `npm run build` must pass and `node --check desktop/plugin.js` must pass after every frontend task.
- The live deck runs on :8785 (backend) and :4527 (preview) — never kill those ports; verify with curl on a scratch port pattern from the jarvis-deck skill.
- Saved scene must render after reload (personal-data rule: saved items must visibly display).

## Review Focus

1. **Gemini returns garbage/wrong shape** — renderer must not crash; malformed parts dropped, scene still renders what it can (pinned by backend validation test, Task 2 step with `part_count_cap` + malformed-part fixtures).
2. **No GEMINI_API_KEY** — build/edit endpoints return 409 with setup hint; the tab shows the message in-place, viewport still renders the saved scene (Task 3 test).
3. **Explode on a part with no explodeDir** — defaults to radial-from-center direction, never NaN (Task 4 renderer unit path via manual curl fixture).
4. **Reload persistence** — POST scene, GET returns identical JSON; deck reload re-renders identically (Task 1 + Task 6 verify steps).
5. **Clicking a part while exploding** — selection raycast must still hit the moved mesh (picking uses live mesh positions, Task 4 manual verify step).
